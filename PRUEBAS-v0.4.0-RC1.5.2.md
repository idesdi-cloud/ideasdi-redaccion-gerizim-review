# Pruebas · ideasDi Redacción Gerizim v0.4.0-RC1.5.2

## Sintaxis

- Todos los archivos PHP deben aprobar `php -l`.
- `assets/admin.js` debe aprobar `node --check`.
- El ZIP debe aprobar `unzip -t`.
- El contenido extraído del ZIP debe aprobar nuevamente PHP y JavaScript.

## Cobertura semántica

- Las siete categorías deben resolver un territorio válido.
- Las 73 combinaciones categoría–tag registradas por la matriz interna deben resolver rol y familia.
- Adobe debe clasificarse como entidad y Software 3D como lente en el caso correspondiente.
- Tags futuros desconocidos deben usar fallback controlado y no convertirse automáticamente en lente.

## Receta y plan

- La receta de Eventos debe ser compacta.
- El ángulo editorial no debe duplicarse íntegramente.
- El plan debe parsear conceptos activados, expansiones, verbos y términos condicionados.
- No se añade una llamada adicional a OpenAI.

## Actualizaciones recurrentes

- `20236` debe bloquearse.
- Un título 2023 con fechas 2026 debe bloquearse.
- Un título 2026 con fechas 2026 debe aprobarse.
- Un título sin año puede aprobar si el resto de la identidad es válido.
- El H1 final debe escribirse en `post_title` sobre el mismo ID.
- Slug, estado, autor, taxonomías e imagen deben conservarse.

## Enlaces

- Una URL de Louis Vuitton no debe considerarse automáticamente página personal de Pharrell Williams.
- Una URL oficial de Adobe puede validar Adobe.
- Un Evento sin cierre oficial debe bloquearse.
- Un Evento con último párrafo y anchor `página oficial del evento` debe aprobar esa regla.
- La URL interna principal no debe duplicarse.

## Meta description

- Menos de 106 caracteres: bloqueo.
- 106–119: válido con aviso.
- 120–145: recomendado.
- 146–150: válido.
- Más de 150: bloqueo.
- Keyword o variante reconocible: obligatoria.

## Interfaz recurrente

- No mostrar el nombre `actualizacion-recurrente-ID.txt`.
- No mostrar opción para quitar ese material.
- Mostrar una explicación transparente del uso interno mientras el workflow permanezca activo.

## Limitación

Las pruebas automatizadas no sustituyen una generación real contra OpenAI ni una instalación controlada en WordPress. Las pruebas editoriales finales deben realizarse en ideasDi con artículos reales de varias disciplinas.
